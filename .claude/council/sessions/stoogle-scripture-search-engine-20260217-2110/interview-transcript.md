# Interview Transcript: Stoogle — Scripture Search Engine

## Round 1

**Q:** What's the core use case — faithful recreation, expanded scope, or completely reimagined?
**A:** Start with a faithful recreation as the first MVP/phase. Future phases: audio transcription for sermons, extracting sermon outlines, highlighting Biblical passages cited, and potentially AI summaries — though theological evaluation of LLM output is a concern and may be out of scope initially.

**Q:** Who is this for?
**A:** Church / small community. Moderate traffic, known users.

**Q:** Tech stack preferences?
**A:** Open to recommendations from the Council.

## Round 2

**Q:** For the curated site list — replicate original, own list, or both + admin panel?
**A:** Start with the original list while also supporting an admin panel to add/remove sites.

**Q:** Search mechanism — Google CSE, own crawler, or hybrid?
**A:** Lean towards Google CSE for first implementation. Wants to understand cost and effort implications of own crawler/index. Has decent confidence in cloud infrastructure support but wants technical feasibility + cloud cost analysis from the Council.

**Q:** Sermon sources — church website, multiple sources, or defer?
**A:** Sermons are on the church website as downloadable audio files. Some recent messages on YouTube. Files are on the public Internet. Would check with church leadership on usage.

## Round 3

**Q:** Budget ceiling for monthly infrastructure costs?
**A:** Between free tier ($0-10/mo) and modest ($10-50/mo). Still wants to see what the "best tools" architecture would cost for comparison.

**Q:** Who manages the curated site list?
**A:** A few admins (2-5 church leaders). Need proper user accounts.

**Q:** Is "Stoogle" the final name?
**A:** Yes, Stoogle is final.
